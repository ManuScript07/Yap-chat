# Внутренний сервис рекомендаций

Микросервис находится в отдельном репозитории `D:/yap-algorithm`. Каноническая схема и RPC принадлежат этому приложению: `20261104195702_feed_recommendation_pipeline.sql`, `20261104213317_personalized_feed.sql` и `20261104225631_feed_media_pipeline.sql` в `supabase/migrations`. Изолированные миграции прототипа находятся в `yap-algorithm/tests/fixtures/migrations` и не применяются к общей Supabase.

Клиент использует Supabase Auth, RPC и Storage. Текстовый `create_feed_post` совместим с прежним контрактом; `publish_feed_post` добавляет до трёх подготовленных фото и необязательную геометку. Триггер ставит задание для непустого текста в `recsys.index_jobs`, а `cmd/worker` сохраняет E5-вектор в той же базе. `recsys.refresh_jobs` объединяет пересчёты профиля и персональной выдачи. Отдельный `cmd/media-worker` проверяет изображения, создаёт очищенные JPEG/превью и физически удаляет файлы через Storage API. У Go нет клиентского HTTP API.

Клиентский контракт: `yap-algorithm/api/supabase.openapi.yaml`. Основные RPC — `get_for_you_feed`, `apply_feed_action`, `record_feed_events`, `set_recommendation_author_hidden`, `reset_recommendation_interests`, `get_recommendation_hidden_authors`. Пагинация использует UUID сессии и позицию; актуальные баны, блокировки, дружба, версии и скрытия проверяются при каждом чтении. Повторы сохраняют UUID и тело запроса, действия по посту дополнительно требуют `action_version`.

Новые публикации: 12 за скользящий час на пользователя. Счётчик не сбрасывается удалением поста. Чтение и обратная связь используют отдельные атомарные квоты, существующие квоты чатов не меняются.

Применять нужно миграцию из этого репозитория через обычный процесс миграций проекта. Миграции/fixtures старого алгоритмического прототипа из `yap-algorithm/supabase` в эту базу не копируются. Worker не меняет схему при запуске.

На текущем ПК миграция уже применена к локальной Supabase. Логин worker настроен отдельно от пользователя postgres и ключей клиента.

```powershell
cd D:/yap-algorithm
./scripts/supabase-local.ps1 -Action setup -AppRoot D:/StudioProjects/Yap_chat
./scripts/local.ps1 -Action model
# После ready, в другом терминале:
./scripts/supabase-local.ps1 -Action worker
# Фото, в отдельном терминале:
./scripts/media-local.ps1 -Action setup -AppRoot D:/StudioProjects/Yap_chat
./scripts/media-local.ps1 -Action worker
```

Сервисная роль `yap_recommendation_worker` имеет доступ только к внутренним функциям очереди. Клиентские функции продолжают использовать существующие проверки активного аккаунта, банов, удаления, блокировки и текущей дружбы. Новые лимиты закрыты в `private.feed_operation_limits` и не меняют квоты чатов. `feed` и `recsys` не надо добавлять к exposed schemas Data API.

Проверки прав: `feed_recommendation_boundary.sql`, `personalized_feed_boundary.sql`, `feed_media_boundary.sql` в `supabase/tests`. Сквозные тесты сервиса запускаются из его репозитория:

```powershell
./scripts/test-supabase-local.ps1 -AppRoot D:/StudioProjects/Yap_chat -WithModel -WithMedia
```

Клиентский порядок фото: `reserve_feed_photo` → обычная загрузка JPEG/PNG в `feed-uploads` с `upsert=false` → `confirm_feed_photo` → опрос `get_feed_photo_status` до `ready` → `publish_feed_post`. В выдаче возвращаются только пути очищенных файлов из `feed-media`. Чтение авторизованное с текущим JWT; подписывание и публичный доступ закрыты. Оригиналы читателям недоступны. Нужна очистка кэша клиента при смене аккаунта или потере доступа. До четырёх активных черновиков; черновик живёт час; фото до 5 МиБ, 20 МП и стороны 8192. Подробные ответы/ошибки зафиксированы в OpenAPI сервиса.

Медиа-роль отделена от рекомендательной: её ограниченный JWT и логин БД не дают доступа к профилям или изменению постов. Токен локального setup истекает через 7 дней; повтор setup и перезапуск продлевают его. Ключ `service_role` и секрет подписи обработчику не передаются. Работающий `media-worker` необходим для подготовки и очистки. Фото без подписи не получает E5-вектор, но его взаимодействия участвуют в авторских источниках.

Точная геометка относится к публикации. Её получают автор и текущие друзья с разрешением точной локации; прочим возвращается только признак «рядом» до 50 км при собственной позиции не старше 12 часов. Видимость в поиске людей рядом на геометку поста не влияет.

Работают персональные снимки «Для вас», показы, чтение, лайки/отмены, отрицательная семантика, скрытие автора и сброс. Поверхности `direct` и `for_you` используют общий профиль. Отдельные выдачи друзей/географии, репосты, комментарии и жалобы добавляются следующими этапами. Flutter-репозитории, кэш и сетевой слой пока не менялись. Облачное развёртывание ещё не проверялось.
