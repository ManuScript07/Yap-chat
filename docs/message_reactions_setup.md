# Реакции: развёртывание и проверка

## Развёртывание

1. Применить `supabase/migrations/202610040001_add_message_reactions.sql` один раз после предыдущих миграций. Для CLI сначала проверить `supabase db push --dry-run`, затем `supabase db push`. Альтернатива — выполнить файл целиком в SQL Editor.
2. Применить `supabase/migrations/202610050001_preserve_message_reaction_order.sql` после первой миграции. Она добавляет порядок реакций; новые замены сохраняют место участника, снятие и повторное добавление перемещают его в конец. Для старых реакций исходный момент установки уже не восстановить — их порядок один раз инициализируется сохранённой ревизией.
3. При первоначальном внедрении реакций обновить существующую функцию: `supabase functions deploy push-message`. Webhook, секрет и FCM остаются прежними; второй webhook не нужен. Функция по-прежнему проверяет `x-webhook-secret`. Для исправлений UI и порядка от 5 октября повторный деплой Edge Function не нужен.
4. Пересобрать приложение. При первоначальном внедрении Drift обновляет схему 24 → 25 без очистки истории; порядок реакций хранится в существующем JSON-кэше, дополнительного обновления схемы Drift нет.

На удалённой Supabase автоматически ничего не применялось.

## Контракт

Серверные коды: `heart`, `like`, `cry`, `fire`, `mind_blown`, `poop`; `null` снимает реакцию. От каждого участника — одна реакция. Клиент использует локальные 2D SVG Noto Emoji: ❤️ 👍 😭 🔥 🤯 💩. Двойной тап ставит сердечко или снимает своё уже установленное сердечко; нажатие собственной пилюли снимает её.

Изображения включены в сборку, не зависят от системных emoji и не скачиваются при показе. Версия, исходные имена и SHA-256 зафиксированы в `assets/reactions/NOTICE`; оригинальное уведомление и Apache 2.0 находятся рядом. Лицензия зарегистрирована в Flutter LicenseRegistry и читается лениво, только при просмотре лицензий. Замена графики не требует миграций или повторного деплоя Edge Functions.

Локальная очередь объединяет выборы за 450 мс, ограничивает быстрые нажатия, отправляет последовательно не чаще одной операции в секунду. При пустой очереди таймера запросов нет. Намерение и расписание повторов сохраняются в Drift. Сервер ограничивает 60 вызовами в минуту и интервалом 350 мс между изменениями реакции на одно сообщение. Это не заменяет сетевую защиту API от DDoS.

События идут через существующий `user:<uuid>:chats`, без новых каналов. Реакция не запускает полный sync истории/списка чатов, не меняет unread/read_at/дату сообщения. Страницы и проверка видимости кэша возвращают состояние в том же ответе. Метаданные далёких окон не заполняют пробелы основной истории и не меняют её курсоры.

Push создаётся один раз за всю историю пары «сообщение + автор реакции», только на чужое сообщение. Замена/снятие/повторное добавление и свои сообщения не уведомляют. Перед отправкой повторно проверяются сообщение, блокировки, аккаунты и актуальность реакции. Push открывает обычный чат.

## Ручная проверка на двух устройствах

1. Текст/фото/голосовое/геоточка: выбрать реакцию через меню, заменить и снять; проверить оба устройства и тактильный отклик.
2. Два последовательных двойных тапа ставят и снимают своё сердечко. Нажатие своей пилюли снимает её. Одинаковые реакции объединяются с двумя перекрывающимися аватарками; разные показываются отдельно, своя выделена. Первый участник слева, второй справа и поверх первого; замена не меняет порядок, снятие с повторным добавлением меняет. Проверить после перезапуска обоих клиентов.
3. Перейти по ответу в далёкое незакэшированное окно. Изменить реакцию с другого устройства, проверить обновление без смены якоря. Пролистать и вернуться вниз.
4. Offline выбрать реакцию, закрыть чат/перезапустить приложение, восстановить сеть: выбор подтверждается. Быстрая серия выборов доставляет последний, а не все промежуточные.
5. Удалить сообщение с ожидающей реакцией: оно не восстанавливается. Заблокировать собеседника: новые реакции недоступны в UI и запрещены сервером в обоих направлениях.
6. Первая реакция на чужое сообщение уведомляет при закрытом приложении. Замена/снятие/повторное добавление не дают второй push; muted-чат не уведомляет. Проверить навигацию из push.
7. Узкий экран/альбомная ориентация: нет переполнения, высота плавно меняется при появлении/снятии, не при замене.

## Автотесты

Flutter: `message_reactions_test.dart`, `message_reaction_coordinator_test.dart`, focused-window cache, sync-coordinator, push payload и существующие регрессионные тесты чатов.

SQL: `supabase/tests/message_reactions.sql` с rollback, включая финализацию аккаунта; `supabase/tests/message_reaction_order.sql` проверяет хронологию, замены, повторное добавление и проекции страниц/окон/кэша. Реальный локальный REST/приватный Realtime: `node supabase/tests/message_reactions_realtime.mjs`; временные аккаунты удаляются в finally.

Настоящая доставка FCM требует ручной проверки пункта 6. Старые `image_reveal_test.dart` и `chat_media_gallery_page_test.dart` используют устаревшие API и не компилируются независимо от реакций; они не включаются в число успешно выполненных тестов.
