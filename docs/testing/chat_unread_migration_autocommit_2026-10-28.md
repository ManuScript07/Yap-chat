# Исправление 25P01 при применении unread projection через CLI

Дата: 28 октября 2026.
Локальный коммит dev: 27187b6, только исправленный файл миграции.

## Причина и состояние удалённой БД

При `npx supabase db push --linked --skip-vault` CLI исполнял верхнеуровневые
SQL-команды без общей транзакции. Исходная миграция рассчитывала на транзакцию
runner: SET LOCAL выдавали предупреждения, LOCK TABLE завершался SQLSTATE 25P01.
Предыдущая проверка миграции на заполненной локальной БД добавляла внешний
BEGIN/ROLLBACK и потому маскировала этот дефект способа применения.

Удалённый проект (Supabase) проверен только SELECT:

- 20261025210630 и 20261025220338 присутствуют в schema_migrations;
- 20261025230324 отсутствует;
- private.chat_unread_counts, private.chat_unread_messages и переименованная
  get_chat_list_page_without_unread_impl отсутствуют. Третья миграция не успела
  создать частичную схему;
- каталог первых двух миграций сверён с видимостью, очисткой и последним
  доступным сообщением: catalog_mismatches = 0.

## Исправление

В том же файле 20261025230324_add_chat_unread_projection.sql все изменения
схемы, блокировка, backfill, триггеры и замена RPC объединены в один
DO $chat_unread_migration$ ... блок. Он атомарен независимо от того, добавляет
ли runner внешнюю транзакцию. Внутренние функции и их алгоритмы сохранены.
Единственный верхнеуровневый вызов backfill заменён SELECT → PERFORM,
поскольку теперь находится в PL/pgSQL-блоке.

statement_timeout=120s устанавливается до старта большого DO: локальная
настройка внутри уже запущенной команды не задавала бы ей начальный deadline.
После успеха выполняется RESET statement_timeout. lock_timeout=5s остаётся
локальным для атомарной транзакции и действует при захвате блокировки.
Ошибка в блоке откатывает и DDL, и backfill, и переименование функции.

Номер/имя миграции сохранены: она ещё не зарегистрирована на удалённой БД.
Ручное изменение schema_migrations, repair, откат первых двух миграций и
повторное создание каталога не требуются. Клиентский код не менялся.

## Проверки

1. Новый chat_unread_migration_autocommit_local.mjs создаёт отдельную временную
   БД на локальном Docker-кластере с минимальными prerequisite-таблицами,
   служебными функциями и 80 сообщениями в четырёх диалогах. Рабочая локальная
   Supabase не понижается и не очищается. Только собственная временная БД
   удаляется в finally; имя проверяется фиксированным regex.
2. Точная старая миграция из 7356f0c запускается psql с autocommit: 25P01
   воспроизводится до создания новых таблиц.
3. В исправленную миграцию инъецируется ошибка ZX001 в самом конце. Проверены
   отсутствие новых таблиц/функций и неизменность исходной page-функции после
   отката. Затем точный исправленный файл успешно применяется повторно.
4. Проверены backfill: 65 unread-ключей и общий badge 25 с учётом read/hide/
   delete/clear/mute/hidden. После commit новые сообщения и read receipts
   обновляют счётчики; page-wrapper возвращает правильный общий итог. Базовые
   ACL проверены. Минимальные функции допуска в этой БД — тестовые заглушки;
   полные права и ограничения реальной Supabase проверены отдельной матрицей.
5. Существующая миграционная проверка на полной локальной Supabase прошла:
   backfill на 400 сообщениях, неизменность старых summaries, права и триггеры.
6. Вся SQL-матрица: 40 passed; количества исходных users/chats/messages/
   attachments до и после совпали.
7. Конкурентная матрица: 26 пар / 52 транзакции passed, с проверенным overlap.
8. Реальные SDK + Drift + WebSocket: три сценария на 1005, 1000 и 2005 чатах
   passed. Проверены пагинация, адресные обновления, общий unread total,
   read/mute/hide/incoming restore, resume/reconnect и навигация за пределами
   загруженной головы. По одному устойчивому пользовательскому каналу на
   устройство; офлайн-просмотр не делает запросов.

AST-граф обновлён: 13788 узлов / 20910 связей; итог сохранён в graph memory.
Отсутствующий tree_sitter_sql остаётся ограничением extractor; сам SQL
проверен выполнением на Docker, а не только графом.

## Повтор на удалённой БД

После получения исправленного файла из корня проекта:

```powershell
npx supabase db push --linked --skip-vault
```

В списке ожидается только 20261025230324_add_chat_unread_projection.sql.
Удалённая схема этим исправлением автоматически не менялась; запросы к
удалённому проекту использовались только для диагностики состояния.
