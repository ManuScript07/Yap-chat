# Ручная проверка списков на локальной Supabase

Данные сохраняются между запусками. Используются действующие миграции,
обычные репозитории приложения, GoTrue-сессии, RLS, Storage и Realtime.
Тестовые люди не запускают фоновые клиенты или отдельные подписки.
Внутри чатов создаётся по одному текстовому сообщению только для превью.

## Быстрый запуск

Запустить Docker Desktop и открыть PowerShell в корне проекта.
Локальная Supabase проекта должна работать; если остановлена — `npx supabase start`.
Выполнить `npm ci`, если зависимости Node ещё не установлены.

```powershell
# Набор уже подготовлен. При повторном вызове он не дублируется.
.\scripts\pagination-lab.ps1 seed

# Запуск приложения на телефоне/эмуляторе с локальными данными.
.\scripts\pagination-lab.ps1 run
```

При одном физическом устройстве выбирается оно, даже если одновременно есть
эмулятор. При необходимости выбрать явно:

```powershell
.\scripts\pagination-lab.ps1 run -Device emulator-5554
```

Скрипт устанавливает `adb reverse tcp:54321 tcp:54321` и запускает профильную
сборку. Для debug добавить `-DebugBuild`. Если PowerShell блокирует скрипты,
можно вызвать `powershell -ExecutionPolicy Bypass -File .\scripts\pagination-lab.ps1 run`.

Тестовый аккаунт открывается автоматически через настоящую локальную сессию.
Яндекс для этого не нужен. Не нажимать выход из аккаунта во время проверки:
локальная кнопка входа создаёт другой анонимный аккаунт без этого набора.
Перезапуск через `run` восстановит подготовленного пользователя.

Рабочий `.env` не изменяется. SQLite и медиа используют существующее
окружение `local`, с отдельной БД и пространством сессии. Обычный запуск
без параметров лаборатории по-прежнему использует рабочие настройки.
Настройки лаборатории запрещены в release, удалённые URL и серверные ключи
не принимаются клиентом. Profile-сборке разрешён HTTP только к loopback.

## Пагинация ленты рекомендаций

Используется тот же тестовый аккаунт и локальная Supabase. После подготовки основного набора:

```powershell
.\scripts\pagination-lab.ps1 seedFeed
.\scripts\pagination-lab.ps1 verifyFeed
.\scripts\pagination-lab.ps1 run
```

`seedFeed` создаёт 65 публикаций от 13 друзей. В наборе есть длинные тексты, группы с одинаковым временем публикации на границах страниц и шесть карточек с фото. `verifyFeed` проходит три RPC под сессией тестового аккаунта и проверяет порядок, размеры страниц, повтор второго курсора и медиа. Для этой проверки достаточно локальной Supabase.

Чтобы добавить фото к существующему набору и сохранить состояния дружбы и заявок:

```powershell
.\scripts\pagination-lab.ps1 -Action seedFeedPhotos
.\scripts\pagination-lab.ps1 -Action verifyFeedPhotos
```

Команда выводит номера карточек. В неизменённом наборе это `002`, `003`, `004`, `006`, `007` и `008`. Если автор больше недоступен в ленте друзей или слот занят вручную, берётся другая доступная карточка. Повтор команды использует те же файлы и позиции.

Набор содержит одиночные фото `900×1200`, `1600×900` и `2048×2048`, сочетание всех трёх, пару `2048×256` и `256×2048`, а также `2048×1`, `1×2048` и квадрат в одной карточке. Цветные области на файлах показывают границы обрезки. Сравни превью в портретной и альбомной ориентации, затем увеличь фото, сдвинь его и вернись назад. `verifyFeedPhotos` проверяет метаданные и скачивает обе версии JPEG из приватного хранилища с сессией тестового пользователя.

На телефоне открой центральную вкладку и прокрути каждую ленту от `Feed Lab 001` до `Feed Lab 065`. Границы страниц проходят после 020, 040 и 060. Проверь отсутствие пропусков, дублей и скачка позиции. Раскрой длинную публикацию, переключи вкладку и вернись. При сбое сети во время подгрузки проверь, что опубликованные на экране карточки остаются видны и кнопка «Повторить» продолжает выдачу. При USB-пробросе выключение Wi-Fi может оставить локальный API доступным.

Для «Рядом» дай приложению обновить геопозицию. Если телефон опубликовал новую позицию, повтори `seedFeed` на компьютере и обнови ленту. Команда переносит те же посты к последней позиции тестового аккаунта и обновляет их даты.

## Панель событий

Открыть **http://127.0.0.1:8743** на компьютере. Панель уже запущена в фоне.
Если её остановили, в отдельном терминале:

```powershell
.\scripts\pagination-lab.ps1 panel
```

Панель не опрашивает БД постоянно. Кнопки вызывают реальные RPC от
соответствующего собеседника:

- новое сообщение в самом старом видимом чате;
- новый входящий чат от пользователя без переписки;
- входящая заявка от свободного пользователя;
- принятие старой исходящей заявки другим пользователем;
- отмена последней входящей заявки её отправителем;
- обновление тестовых геопозиций вокруг текущей позиции владельца.

Последний сценарий — служебное обновление тестовых координат; серверные
правила расстояния, активности и фильтров остаются прежними.
После первого открытия «рядом» дать приложению получить геопозицию,
нажать кнопку обновления координат в панели и обновить ленту в приложении.
Кнопка также обновляет сроки активности тестовых людей после долгого перерыва.

После удаления/повторного создания набора перезапустить панель.
Остановить foreground-панель можно Ctrl+C; фоновая PID записана в
`.local/pagination-lab/manual/panel.pid`.

## Что находится в наборе

| Список | Начальное число | Обычные страницы |
|---|---:|---|
| Чаты | 220 | 50 + 50 + 50 + 50 + 20 |
| Свои друзья | 160 | 50 + 50 + 50 + 10 на сервере |
| Входящие заявки | 60 | Загружаются целиком |
| Исходящие заявки | 60 | Загружаются целиком |
| Люди рядом | 150 видимых из большого пула | 30 × 5 |
| Друзья тестового профиля | 240 видимых | 8 страниц по 30 |

У тестового профиля 241 связь дружбы, но текущий пользователь из чужого
списка исключается. В наборе 362 профиля; примерно у 75% есть настоящие
JPEG в приватном bucket avatars, у остальных обычная заглушка.
Одинаковые даты/имена специально пересекают границы страниц.
Исходящий лимит чатов не отключён: основной объём — входящие диалоги.
Список «создать чат» и выбор друзей в настройках видимости используют тех же
друзей и тоже пригодны для проверки подгрузки.

Искать:

- `Глубокий чат Лаб` — чат из конца истории;
- `Дальний друг Лаб` — свой друг из конца списка;
- `Последний друг профиля Лаб` — конец списка друзей чужого профиля;
- `Одинаковое имя Лаб` — несколько строк с одинаковой подписью;
- username профиля с большим списком друзей показывает панель.

Поиск списка друзей чужого профиля сейчас фильтрует подгруженную часть.
Для поиска его последнего друга сначала подгрузить этот список полностью.
В «рядом» проверяются фильтры пола/возраста; текстового поиска там нет.
Кэш «рядом» ограничен 150 людьми и двумя наборами фильтров — это штатные правила.

## Исправленная точность курсора друзей

Первоначальная интеграционная проверка выявила потерю точности курсора:
серверная дата дружбы содержит микросекунды, а `CachedFriendListStates`
сохраняет её с точностью до секунды. При равных датах на границе страницы
на свежем наборе приложение сохраняло **154 из 160** друзей, хотя API
возвращал все 160. После последней страницы `hasMore` уже был false.

Исправление от 30 октября сохраняет микросекунды в локальной схеме версии 29.
При обновлении старые друзья доступны офлайн, а непрерывность списка
проверяется заново обычными страницами по мере подгрузки. Чистить данные
приложения не нужно. Даты набора не округлялись.

Отдельная проверка на текущем, уже изменённом вручную наборе загрузила
**165 из 165** друзей за четыре страницы, включая восстановление старого
неполного кэша, перезапуск и офлайн. Результат и точные курсоры:
`.local/pagination-lab/manual/friend-cursor-verification.json`.

## Ручная матрица

1. **Обычная прокрутка.** Пройти каждый список до конца, вернуться наверх,
   повторить. Смотреть на дубли, пропуски, скачки, конец подгрузки.
2. **Событие внизу.** Прокрутить чатикс вниз и нажать «сообщение в старый
   чат». Затем вернуться наверх: изменённый диалог должен быть первым и
   существовать в единственном экземпляре. Повторить с новым входящим чатом.
3. **Поиск за первой страницей.** На свежем кэше искать специальные имена
   чата и своего друга до прокрутки. Очистить запрос, продолжить подгрузку:
   найденная строка не должна нарушать курсор или дублироваться.
4. **Поиск во время событий.** Оставить активный запрос, вызвать новое
   сообщение/заявку, стереть запрос. Проверить порядок и счётчики.
5. **Заявки.** Прокрутить входящие/исходящие; вызвать три действия панели.
   Проверить исчезновение/появление строк и переход принятой заявки в друзья.
6. **Кэш.** Подгрузить несколько страниц, выполнить поиск, перезапустить
   приложение. Повторить без соединения с локальной Supabase: сохранённые
   строки должны оставаться доступными в рамках правил каждого списка.
7. **Друзья профиля.** Открыть профиль из панели по username, перейти в его
   друзей. Проверить 8 страниц, одинаковые имена, поиск после подгрузки,
   возврат из профиля друга и офлайн-повторное открытие.
8. **Рядом.** Пройти 4 страницы, сменить пол/возраст, проверить пустой
   результат (например, возраст 18–22), вернуть фильтры и повторить офлайн.
9. **Геометрия.** Повторить основные проверки в альбоме, с клавиатурой и
   увеличенным шрифтом. Сравнивать плавность предпочтительно в profile.

Для офлайна важно прекратить именно доступ к локальной API. На USB
выключенный Wi-Fi не обязательно прерывает adb reverse. Можно временно
убрать проброс и вернуть его:

```powershell
adb -s <ID> reverse --remove tcp:54321
adb -s <ID> reverse tcp:54321 tcp:54321
```

## Автопроверки и очистка

```powershell
.\scripts\pagination-lab.ps1 verify  # Серверные страницы/поиск, без очистки
node --test tools/pagination_lab/guards.test.mjs
```

Проверка всех клиентских дисковых кэшей на **свежем** наборе:

```powershell
node tools/pagination_lab/main.mjs prepare
flutter test test/diagnostics/pagination_lab_cache_local_test.dart --dart-define=PAGINATION_LAB_CACHE_TEST=true
```

Проверка исправления друзей работает и после ручных изменений количества
друзей в существующем наборе, не пересоздавая его:

```powershell
node tools/pagination_lab/main.mjs prepare
flutter test test/diagnostics/friends_cursor_local_test.dart --dart-define=PAGINATION_LAB_CACHE_TEST=true
```

Проверка стабильности людей рядом: страницы до 150, офлайн-снимок и
намеренно задержанный ответ старой страницы. Используется отдельный
синтетический пользователь, квота владельца не расходуется.

```powershell
node tools/pagination_lab/main.mjs action nearby-refresh
flutter test test/diagnostics/nearby_stability_local_test.dart --dart-define=PAGINATION_LAB_CACHE_TEST=true
```

Прогон использует восемь чтений nearby. Между быстрыми повторными запусками
нужно дождаться следующего минутного окна серверной квоты. После обновления
приложения поздние ответы завершённых попыток не должны показываться после
ошибки/пустого состояния; старый снимок сохраняется до нового успешного refresh.

Деструктивная только для этого набора проверка Realtime/очистки с последующим
восстановлением свежих данных: `node tools/pagination_lab/check.mjs --reset-fixture`.
Выполнять до ручной проверки, затем перезапустить панель и приложение.

После окончания удалить **только этот набор**:

```powershell
.\scripts\pagination-lab.ps1 cleanup
```

Очищаются пользователи с меткой конкретного запуска и их связанные данные/
файлы через Storage API; остальные пользователи не затрагиваются. Это
проверено отдельным посторонним аккаунтом и файлом. Ни один скрипт не
принимает удалённый Supabase URL. Служебные пароли/сессии в `.local/`
исключены из Git; не публиковать эту папку и тестовый APK с локальной сессией.
